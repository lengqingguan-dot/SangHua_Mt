# 画面版 V0.1：交付与技术路线

更新日期：2026-09-28。

## 确认后的方向

画面版是 2D 俯视 RPG：每个逻辑房间一张可移动地图，不是以静态背景配文字框为主要界面的视觉小说。现有地图 ID 和房间连接关系继续有效，剧情对话在需要时覆盖地图。

文字版已移至 `文字版/` 并保留拆分时的工作内容；画面版在 `画面版/` 独立修改。两者当前是独立副本，后续共同规则的修复需要分别合入；本轮没有跨目录共享依赖，以便任意版本目录独立分发。

## 为什么当前仍是网页入口

HTML 是界面结构，CSS 是样式，JavaScript 才是逻辑语言，Canvas 是绘图接口。JavaScript 并非不能开发游戏；当前选择它是为了保留已有规则并尽快验证俯视地图交互，不等于它是这款游戏长期开发的最优方案。

本轮没有启动新的引擎迁移，也没有安装 Godot、Unity 或导出 EXE。此原型是技术与交互验证版本，不是最终技术栈承诺。

## 两条后续路线

| 方向 | 现有代码复用 | 内容制作 | 成本与限制 |
| --- | --- | --- | --- |
| 保留 JavaScript，逐步工程化 | 高，规则和存档迁移可继续使用 | 需接入或制作地图／动画编辑工具 | 初期改动小，但维护工具和大型内容生产的负担会增加 |
| 迁移 Godot，使用 GDScript 或 C# | 数据、规则设计、美术可复用，JS 逻辑需移植 | 可利用场景、TileMap、2D 物理和动画工作流 | 初期迁移工作量高，要重新验证剧情、战斗、掉落及存档，不是改扩展名即可 |

针对“长期制作大量独立房间地图”的目标，我更倾向在扩大内容生产前评估 **Godot**。它提供专用 2D 渲染、物理、TileMap 和精灵动画工具，能减少自己维护编辑工具的负担。[Godot 官方 2D 简介](https://docs.godotengine.org/en/stable/tutorials/2d/introduction_to_2d.html)

若只面向 Windows 桌面且重视通用语言，可评估 Godot + C#；若希望保留浏览器发布选项，则优先评估 GDScript。当前 Godot 官方源码／文档仍注明 Godot 4 的 C# 项目不能导出到 Web；这是一项引擎导出限制，不是 C# 语言本身的限制。[官方 C# 文档源码](https://github.com/godotengine/godot-docs/blob/master/tutorials/scripting/c_sharp/index.rst)

“解压即玩”也不一定意味着 HTML；可以选择桌面打包路线。但正式承诺支持哪些操作系统前，需要实际导出并在无开发环境的机器上验收。

## 如果决定迁移

1. 保留文字版和当前地图原型作为行为参考，不先删除旧系统。
2. 提取纯数据：房间、物品、NPC、技能、稀有度和掉落表；带 JS 回调的剧情必须拆为显式事件数据，不能直接当 JSON 导入。
3. 只移植一个纵向切片：起始矿井五张图、移动、对话、物品、一个战斗和存读档。
4. 对照当前回归测试重建新引擎测试，重点守住料理永久加成、单一目标锁定、技能书学习／升级、概率掉落、战败读档。
5. 通过切片验收后，再确定正式引擎和存档兼容方案，逐区域扩展。

当前原型的地图坐标、障碍矩形、房间连接和交互锚点可以作为迁移输入；Canvas 绘制代码不能直接变成 Godot 场景，像素占位图也应逐步替换成正式素材。

## 本轮实现边界与验收

- 基础世界 345 个 roomId 对应独立布局，首批五张为手工配置。
- 其他地图是稳定生成的基础布局，不宣称 345 张关卡均已完成美术与关卡设计。
- 回合制战斗保留；地图不是即时动作战斗系统。
- 对话逐句／跳过回调、移动阻塞、钥匙门限制、同名敌人锁定、坐标存读档和离线 Mod 都加入了测试。
- 全工作区 128 项通过（文字版 56，画面版原玩法 56，地图与适配 16）。
- 浏览器曾确认标题页、开场对话、跳过与命名。小屏高度问题随后修复；本轮续接时原浏览器工具未提供，Computer Use 返回 native pipe unavailable，最终页面未重新截图验收。没有绕过安全提示，也没有安装替代控制服务。
- 玩家仍需人工试玩验证听感、移动手感、手机触控、文件选择与下载体验；当前不能将单元测试结果描述为完整端到端通过。
