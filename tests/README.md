# 游戏回归测试

在项目目录执行（只使用 Node.js 内置模块，无需安装依赖）：

```sh
node --test tests/cooking-bonuses.test.cjs tests/update029.test.cjs
```

测试加载实际游戏脚本，仅替换浏览器界面、文件选择器和计时器。保存与读取使用真实 `saveGame()` / `loadGame()`，文件内容暂存在内存，不接触玩家存档。

`update029.test.cjs` 直接按 `index.html` 加载全部 68 个脚本，验证目标锁定、同模板敌人身份、十个攻击技能、初始自带《仇恨》、背包学习与技能栏升级、武器条件、六个副本、概率掉落与地面拾取、旧版奖励迁移、演武、旧档迁移、计时器和战中存读档。当前共 101 项测试（料理 15 项、玩法与交互 86 项）。通关测试通过真实单位死亡和战斗结算触发，不代表已完成数值平衡试玩。

尺寸显示测试覆盖名称和肢体选择项去括号、脚码与罩杯写入介绍、等品质同名不同尺寸不堆叠、带分组键查看正确物品、同类地面拾取不混尺寸，以及旧散落肢体和尸体中预生成部位的读档迁移。迁移不重掷评分、品质和尺寸，重复读档不叠加介绍文字。副本文案检查每角色各部位六档描述均有区别，没有仅替换姓名的整段克隆。浏览器另验证同名38/39码、C/D罩杯物品分组及详情显示，预览位于 `tmp/limb-introduction-detail.png`。

六处副本逐一验证出口只在初始房间、击败首领后的首领房间出现；普通房和战斗中调用离开函数均失败，未清完岔路仍可从已击败首领的房间离开，读档后也保持该规则。面板关闭后的小地图移动没有延迟计时器，旧位置或旧世界的点击回调失效。浏览器测试实际保留首领遭遇，击败首领前后检查出口显示。

副本测试检查统一入口卡片、描述与实际怪物等级、学院大石门不重复显示、进入和重置的地点与战斗限制，以及未通关时重置与取消后的进度保留。所有副本默认开放；测试覆盖未读告示、未挑战外庭、未通关任何副本的新状态，及缺少解锁字段或字段为假的旧档，逐一进入六处副本；城镇快捷入口也无需通关解锁。

六副本各35组随机源（含固定零值与边界值）从出口独立推导平面坐标，逐一验证无重叠、方位一致、连通、岔路、首领距离10～12步、10～15间普通房及总数12～17间。还验证每副本恰好使用一种小怪、一个首领及三类房间，并构造“出入口互逆但几何方位错误”的反例，确认会被拒绝并修复。

肢体测试覆盖每部位六档不同的描述、评分与尺寸不重掷、真实死亡、成对一致、肢解拾取、魔偶识别与反复存读档。旧短副本读档时自动修复空间并补足普通房，保留房间ID、已清怪进度、物品、通关标记和当前战斗；旧支援NPC及其尸体、散落肢体会归并到小怪。新生成与旧存档的部位描述均不再输出“保存状况”品质后缀。

独立浏览器验证脚本位于 `tmp/dungeon-ui-check.cjs`，使用本机浏览器及开发环境的 Playwright（不属于玩家运行依赖）。已确认入口卡片与普通物品实际尺寸一致，检查房间数量和类型，并实际点击小地图沿首领路线逐步前进、反向返回，再走通详情、退出、继续、取消重置、确认重置和学院入口；截图保存在 `tmp/dungeon-*.png`。

撤走的梯子为可携带物品：在 #24 拾取，到 #23 后从背包使用爬上 #22，保留原有从井口返回矿道的用途且不消耗。测试覆盖单件及批量拾取、地面不提供直接使用、背包按钮、丢弃后重拾、存读档、持有检查、错误地点和战斗限制，其他固定梯子仍不可拾取。

新版已学技能成功释放时统一输出发动提示，包括仇恨、誓言等自身强化技能。攻击技能先显示发动记录，再显示伤害或闪避；未满足条件、重复使用等失败情况不会输出成功发动记录。测试覆盖全部十二个技能的提示和击杀时的输出顺序。

传送类场景道具共用即时切换逻辑，成功后只输出一条统一颜色的字幕；没有专用字幕时自动生成抵达文字。测试遍历标准传送门，并检查特殊木梯、教堂、城镇、传送阵、魔镜、矿坑和六处副本出入口。钥匙、卫兵、石块、伤害和已访问目的地条件不变，旧传送延迟不再创建计时器。战斗技能按钮只显示名称，技能栏详情保留完整效果；消耗、冷却和禁用判定照常生效。

普通 NPC 对话由播放器统一保留一行空白，不再叠加逐句换行回调。监工对白使用催工与收取劳动指标的口吻；测试通过真实输出函数检查逐句推进和跳过播放的间距，同时确认交付与击杀通行条件保持不变。

文字版新遭遇直接自动开打，战斗详情不再显示“开始／继续战斗”及“保存战斗”按钮；普通存档功能和旧战斗快照仍保留。读档、逃跑后返回自动从原来的下一步继续，不重置行动预算。测试验证无需额外点击即可推进至胜利、开场锁定目标、重复启动不会产生多条行动序列、读档后不重复执行已使用的玩家行动，以及存档取消后恢复原遭遇。

监工通行测试覆盖普通监工中立、主动攻击、99块不足、100块放行、只扣一次、动态石块、交付后仍可对话、真实击杀放行、两种路线存读档、旧档兼容、战中及异地操作拒绝和读档后的旧上行操作失效。和平放行标记为 `gameFlags.mineSupervisorPaid`；旧档中已移除的监工不会复活或重新收取石块。

覆盖五类料理、叠加、经验不足以升级、连续升级、反复存读档、旧版迁移、生命上限饰品、战斗临时技能、战斗中食用、胜利经验结算、战败后读档和重新开局。此测试不代替浏览器界面测试。

## 属性和存档约定

- `player.permanentBonuses` 保存 `maxHp`、`atk`、`def`、`agi` 的永久加成。当前的 `all` 料理仍只增加这四项，不改变技力。
- 等级基础属性加上永久加成后，生命上限再应用饰品百分比并取整。装备攻击、防御等仍由原有角色属性查询函数计算。
- 食用、升级、读档以及战斗结束共用这份永久成长记录。战斗技能的临时数值不进入该记录。
- 存档版本为 4（0.2.9），兼容已有 v2 → v3 料理迁移；新增技能、副本和前台遭遇状态。永久加成随 `player` 一起序列化；玩家运行游戏不需要 Node.js 或其他新依赖，仍可解压后打开原来的入口。

## 旧存档限制

读取缺少永久加成字段的 v2（或无版本号）存档时，根据已保存属性与当前等级基础属性的正差值做一次迁移。生命上限会考虑现有饰品倍率，以保留存档中的可见上限。新版保存后不会重复推算。

旧存档没有食用历史，也没有保存前台战斗快照。因此这只是兼容性推算：旧战斗技能数值、旧数值平衡版本、饰品取整和装备/食用先后顺序可能影响结果，无法保证恢复原始食用量。已经清除加成并覆盖保存的存档无法自动找回损失，最好保留升级前的原始存档备份。
